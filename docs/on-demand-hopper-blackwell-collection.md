# Hourly on-demand Hopper / Blackwell supply collection

Status: **partially implemented**. Do not report a provider as having zero capacity merely because an endpoint fails, returns no rows, lacks a credential, or publishes only a SKU. Existing Vast snapshots run every 10 minutes by default (thus at least hourly when enabled). The existing Runpod catalog runs hourly when enabled, but its current normalization labels all rows `spot` and does not preserve an instance-shape-specific live count; **do not use its normalized rows as on-demand evidence until fixed**. The new migration `0012` exposes candidate on-demand Vast rows and correctly labeled provider observations without inventing missing values. No new provider credentials or paid allocations were used.

## Target contract

Collect **one read-only snapshot per provider per hour** where permitted. Record attempted_at, HTTP result, parser status, offer/SKU ID, product/interface (raw VM vs dedicated endpoint), contract (`on-demand` only), raw GPU name, family (H100/H200; B200/B300; GB200/GB300), number of physical GPUs in *one* allocation (1, 2, 4, 8, etc.), region/zone, memory per GPU, interconnect if disclosed, hourly **total instance** price, currency, additional fees, availability value, availability semantics, and raw retrieval ID. Preserve price per GPU separately only if explicitly quoted; never divide a node price without labeling it derived. GB200/GB300 rack or NVL72 prices are not standalone B200/B300 prices. Never infer two connected cards from two single-card listings. Separate on-demand from spot, reserved, token API, and serverless products.

Availability evidence classes: `live_offer` = currently rentable exact offer, `live_capacity` = provider-reported free capacity at an exact shape and region, `product_catalog` / `catalog_price` = advertised only, `source_document` = page captured but not machine-readable. `unknown` is not zero. Preserve explicit zero and explicit unavailable status as observations; distinguish empty successful complete responses from failed/incomplete pagination. A live offer is still not a launch guarantee. Time series should retain historical snapshots, including disappearances via successful complete polls; a latest-ever row is stale after a failed poll. Report last successful poll and age separately. No provisioning in collectors.

## Allocation-shape collection rules

The unit of collection is one rentable allocation, not one GPU SKU. Collect every supported physical-GPU count for each Hopper and Blackwell model. Query at least 1, 2, 4, and 8 cards when the provider supports these counts. Retain other counts that the provider returns. Keep H100 and H200 separate. Keep B200 and B300 separate from GB200 and GB300. A MIG slice is not a physical card.

Record the queried count and the returned count separately. Record the region, market tier, contract, interface, price unit, and evidence class for each shape. Preserve a quoted GPU-hour price. A calculated instance-hour price must have a derived label. Do not treat a maximum supported count as available capacity. Do not add single-card offers to create a multi-card shape.

A snapshot is complete only after all required shape queries succeed. Retain raw responses from incomplete polls, but exclude their normalized observations from availability reporting. When the API does not expose a region or tier for an exact shape, leave it unknown. An empty region list is not an explicit zero count. Confirm the meaning of an availability status before calling it live capacity.
